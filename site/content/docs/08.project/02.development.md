## Build and run

```powershell
cargo build                          # debug build -> target\debug\winsploit.exe
cargo run                            # the dashboard (needs an interactive terminal)
cargo run -- list                    # non-interactive: catalog + install status
cargo run -- hashid <hash>           # the built-in hash identifier
cargo run -- --catalog .\tools.yaml  # use a specific catalog
```

::callout{type="note"}
A running `winsploit.exe` locks `target\debug\winsploit.exe`, so `cargo build` fails with "failed to remove file" until you close it.
::

## Tests and lints

```powershell
cargo test                                   # all unit tests
cargo fmt --all
cargo clippy --all-targets -- -D warnings
```

UI tests render into ratatui's `TestBackend` and build the app from the real `tools.yaml`, so a change to visible strings or layout usually means updating their assertions. Tests never write the real `%APPDATA%`.

## CI

On every push and PR, `windows-latest` builds in release mode and smoke-tests `--version` and `list`. Pushing a `v*` tag builds and publishes a release zip.

## This website

The site lives in `site/`: Nuxt, Nuxt Content for these docs, GSAP and Lenis for motion. The catalog pages and every count on the site are generated from `tools.yaml`, and the live demo runs the real web view UI from `src/web/` against a simulated session.

```powershell
cd site
npm ci
npm run dev        # http://localhost:3000
npm run generate   # static build in .output/public
```

Docs pages are Markdown files in `site/content/docs/`. Pushing to `main` deploys the site to GitHub Pages.
