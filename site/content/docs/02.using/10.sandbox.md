title: Windows Sandbox
description: Run debuggers and other reversing tools in a throwaway VM with S.
group: Using Winsploit
---

Debuggers run the binary you're looking at. For a CTF crackme that's usually fine, until it isn't. Press **`S`** on a tool marked *sandbox*, give it the challenge file or folder, and Winsploit starts the tool inside **Windows Sandbox**, a throwaway VM that Windows wipes when you close it.

| Tool | Sandbox |
|---|---|
| x64dbg, dnSpy | recommended (they execute the sample) |
| Cutter, Ghidra, radare2, Detect It Easy | optional |

## What's shared with the VM

- The tool's own Scoop folder, plus runtimes it needs (the JDK for Ghidra), is mapped in **read-only**. Nothing gets installed inside the VM.
- The sample's folder is mapped **read-only** to `Desktop\samples`. If you pick a single file, the tool opens it directly.
- **`Desktop\out`** is the only writable folder. On the host it's `%LOCALAPPDATA%\winsploit\sandbox\<time>-<tool>`, next to the generated `.wsb` file.
- **Network is off** unless you turn it on for this run with `Tab` in the prompt. Clipboard, GPU, audio, camera and printers are always off.

Your profile, `AppData`, Scoop, `Program Files` and Windows itself are refused as the sample folder, so you can't accidentally hand the VM your home directory.

::callout{type="note" title="Terminal only"}
Sandbox runs start from the terminal dashboard, never from the [web view](/docs/web-view/overview). The browser can't choose host folders to map into a VM.
::

## Requirements

Windows Sandbox needs Windows 10/11 **Pro, Enterprise or Education** with virtualization turned on. It isn't available on Home. Enable it once from an admin PowerShell, then reboot:

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Containers-DisposableClientVM -All
```

The tool must be installed on the host first (`i`), because the VM uses the host's Scoop copy.

::callout{type="warning" title="A seatbelt, not a malware lab"}
VM escapes exist, and anything you copy out of `Desktop\out` is yours to handle. Analyse real malware in a dedicated VM with snapshots.
::

## In the catalog

A tool opts in with `sandbox:` and, if it needs runtimes, `sandbox_deps:`. See [tools.yaml](/docs/catalog/tools-yaml).

```yaml
  - name: ghidra
    # ...
    sandbox: optional            # never (default) | optional | recommended
    sandbox_deps: [temurin25-jdk]
```

Only Scoop-installed `gui` and `stream` tools can be sandboxed. The catalog check reports anything else.
