CTF work is organised by challenge, so Winsploit is too. Press **`C`** to pick or create a challenge. Each one is a folder under `%USERPROFILE%\ctf`, grouped by event:

```text
ctf\picoCTF-2026\rev-crackme1\
    challenge.yaml   event, name, target, flag format
    files\           challenge files (copies; the originals are untouched)
    logs\            a log per run started while it's active
    out\             files tools write ({out} in recipes)
    flags.txt        flags the catcher found
    notes.md
```

## While a challenge is active

- Tools run in its folder: switching to it makes it the [working folder](/docs/using/running-tools#the-working-folder) (`d` still goes anywhere else).
- Run and install [logs](/docs/using/logs) go into its `logs\` folder.
- The [flag catcher](/docs/using/flags) saves to its `flags.txt` and trusts its **flag format** (for example `ACME` for `ACME{…}`) like the well-known prefixes.
- [Recipes](/docs/using/recipes) fill in its target, files, `out\` folder and wordlist.
- The header shows `event / challenge · target` instead of the tagline.
- It's remembered and reopened at the next start.

## Keys

In the `C` picker:

| Key | Action |
|---|---|
| `↑` `↓` · `j` `k` | Move in the list |
| `Enter` | Switch to the selected challenge |
| `n` | New challenge: prompts for event, name, target, flag format, then a file to copy in |
| `t` · `l` | Edit the active challenge's target · flag format |
| `f` | Copy a file into `files\` (the original is untouched) |
| `m` | Open `notes.md` |
| `o` | Open the challenge folder in Explorer |
| `x` | Leave the challenge (no challenge active) |
| `Esc` · `q` · `C` | Close |

## In the web view

The top bar shows the active challenge and its target, and a menu switches between **existing** challenges. Creating one, editing it and copying files in stay in the terminal. The browser only ever sends a challenge id (`event/challenge`), and ids only resolve to folders found by scanning `%USERPROFILE%\ctf`, so a page can never name a path.
