---

Edit `tools.yaml`. No code changes are needed, and the header of that file documents every field.

## A native tool (Scoop)

```yaml
  - name: gobuster
    categories: [recon, web]
    description: Directory / DNS / vhost brute-forcing
    exe: gobuster          # used to detect the install (PATH probe)
    scoop: gobuster        # Scoop package to install
    run_cmd: gobuster      # command actually launched
    args_hint: 'dir -u https://example.com -w "{app:seclists-lite}\common.txt"'
    bucket: security       # optional; main-bucket tools omit it
```

A bucket Scoop doesn't know by name also needs its URL in the top-level [`buckets:`](/docs/catalog/tools-yaml#buckets) map, so Winsploit can add it on first install.

## A Python tool (pipx)

```yaml
  - name: arjun
    categories: [web]
    description: HTTP parameter discovery
    exe: arjun
    install: pipx
    pipx: arjun            # or arjun==2.2, or git+https://github.com/owner/repo
    run_cmd: arjun
    args_hint: "-u https://example.com/endpoint"
```

Each tool gets its own venv. If pipx is missing, Winsploit installs Python and pipx through Scoop first.

## A tool nobody packages

Add a Scoop manifest to [`bucket/`](https://github.com/tahabenissa/nasrya-toolbox/tree/main/bucket) with a pinned `url` and `hash`, then set `bucket: winsploit` in the entry. See [Winsploit's Scoop bucket](/docs/catalog/bucket).

## Check it

```powershell
cargo test             # validates every bucket manifest against the catalog
winsploit list         # loads the catalog and prints every tool with its status
```

`winsploit list` reports **every** problem in the file at once. A dev build reads the checkout's `tools.yaml`, so a rebuild isn't needed to try a catalog change.

::callout{type="tip" title="Contributing a tool?"}
Only add tools that really work natively on Windows, and use `note:` to document caveats. Then open a PR. See [Contributing](/docs/project/contributing).
::
