## The start-up menu

After the splash screen Winsploit asks how you want to work:

| Choice | What it does |
|---|---|
| **Continue in terminal** | The keyboard dashboard, right here |
| **Open in browser** | Starts the [web view](/docs/web-view/overview) and opens it. The terminal stays in charge |

Skip the question with `--no-web` (terminal only) or `--web` (always open the browser too).

## The welcome tour

The first time, a three-card tour covers the essentials:

1. `↑` `↓` move through the tools · `←` `→` switch category
2. `⏎` runs a tool in its own terminal · `i` installs it
3. `/` filters · `?` shows every key · `t` changes the look

`Esc` skips it. Once finished, it's remembered in `%APPDATA%\winsploit\settings.yaml` and won't show again.

## What happens in the background

- **Detection** runs off the UI thread: every tool's `exe` is looked up on `PATH` × `PATHEXT`, and tools with a [`verify:`](/docs/catalog/verify-and-notes) check run it. Status glyphs fill in as results arrive.
- **The console** (terminal 0) shows which catalog was loaded, and warns if a `tools.yaml` in the current directory was ignored.
- **Nothing runs** until you press a key. Winsploit never installs or launches on its own.

::callout{type="tip"}
If your console font shows boxes or `?` instead of `● ○ ◐` and borders, press `t` and set borders and glyphs to *ascii*. See [Appearance](/docs/using/appearance).
::
